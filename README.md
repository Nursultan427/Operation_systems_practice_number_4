# 3. Объяснение результатов через GIL

## Что такое GIL?

GIL (Global Interpreter Lock) — механизм CPython, который ограничивает одновременное выполнение Python-кода несколькими потоками в одном процессе.

### CPU-bound задача

Суммирование большого количества чисел является CPU-bound задачей, поскольку основная нагрузка приходится на процессор.

При использовании 4 потоков выполнение Python-кода ограничивается GIL. Поэтому несколько потоков не обязательно ускоряют вычисления.

В некоторых случаях 4 потока могут работать даже медленнее одного из-за дополнительных затрат на создание и переключение потоков.

### Почему процессы могут ускорить вычисления?

Каждый процесс имеет отдельный интерпретатор Python и собственное адресное пространство.

Поэтому несколько процессов могут выполнять вычисления параллельно на разных ядрах процессора.

Однако процессы требуют больше ресурсов, чем потоки, а также имеют дополнительные расходы на создание процессов и передачу данных между ними.

---

# 4. Почему потоки эффективны для сетевых задач?

Загрузка веб-страниц является I/O-bound задачей.

Большую часть времени программа не вычисляет данные, а ожидает:

* ответа сервера;
* передачи данных по сети;
* завершения операции ввода-вывода.

Во время ожидания одного потока другой поток может выполнять свою работу.

Поэтому `ThreadPoolExecutor` обычно значительно быстрее последовательной загрузки нескольких URL.

Для сетевых задач использование потоков часто является более эффективным и простым решением, чем создание отдельных процессов.

# 5. Разделение памяти

В работе также исследуется отличие потоков и процессов при работе с глобальным списком.

Используется глобальный список:

```python
shared_list = []
```

### Поток

Поток изменяет общий список:

```python
shared_list.append("Изменение из потока")
```

После завершения потока изменение видно родительскому коду.

Это происходит потому, что потоки одного процесса используют общую память.

### Процесс

Дочерний процесс также изменяет список:

```python
shared_list.append("Изменение из процесса")
```

Однако изменение не появляется в списке родительского процесса.

Это происходит потому, что процессы имеют отдельные адресные пространства и отдельную память.

### Вывод

**Потоки:**

```text
Один процесс
    |
    ├── Поток 1
    ├── Поток 2
    ├── Поток 3
    └── Поток 4

Общая память
```

**Процессы:**

```text
Процесс 1 → собственная память
Процесс 2 → собственная память
Процесс 3 → собственная память
Процесс 4 → собственная память
```
